# Architecture

    log text --> readLines --> lines per package, with -json events unpacked and CI timestamps removed
    parseStream --> one Report per WARNING: DATA RACE block: two accesses, their frames, where each goroutine started, the test and package
    Review --> groups by the two code locations --> races ranked by tests hit, hints, and lines in more than one race
    Compare --> two summaries --> new, gone and still there, matched by function names

- **Location:** the first frame on each side that isn't the standard library, `_testmain.go` or `<autogenerated>`. The frame just above it is shown as "via", such as `runtime.mapaccess2_faststr`. When a side has no such frame, the first known frame is used and RS108 is added.
- **Test names:** `-json` events carry the test. Plain output is matched to the next "race detected during execution of test" line: without `-v` the `--- FAIL` line comes just before it, and with `-v` the latest `=== RUN` line names the test.
- **Packages:** `-json` events carry the package. Plain output takes it from the next `FAIL` or `ok` line.
- **Hints** come from frame names, files and the two locations. Each report in a group adds its hints, because one report can show `runtime.growslice` and another not.
- **Compare** ignores line numbers, so an unrelated edit doesn't make a race look new. The cost is that two races in the same pair of functions count as one.

Key choice: one standard-library Go file run with `go run`. See `decisions/`.
